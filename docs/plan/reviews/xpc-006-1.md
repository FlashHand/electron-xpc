### Recorded deviation

The Error Semantics section also states that `send()` resolves `null` when the remote handler itself
throws. The harness does not exercise a throwing handler — this one clause is source-verified only
(`src/utilityProcess/xpcUtilityProcess.helper.ts:188-192`, `catch → ret = null`). It is kept because
it is pre-existing library behavior shared by all four layers, not a claim about this sprint's new
code, and omitting it would leave the "never throws to the caller" contract half-stated. Flagged
rather than silently included.

## Drift note

section — pre-existing drift from before this sprint, not introduced by it. Mirroring xpc-006's edits
required adding both sections in full, so the CN file grew more than the EN one. The two are now
section-for-section equivalent.

Unchanged and worth knowing: `README_CN.md` does not ship in the npm tarball. `files: ["dist"]` is an
allowlist and npm only force-includes `README.md`, `LICENSE`, and `package.json`. That predates this
task; the Chinese README has always been GitHub-only. Not fixed here because the task forbids
restructuring, and adding it to `files` is a packaging decision, not a docs one.
