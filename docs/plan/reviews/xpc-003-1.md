## Self-send re-entrancy (T4)

Traced by reading both sides. Utility A invoking a handler A owns produces two `__xpc_finish__`
messages on one port in opposite directions:

1. main `__xpc_exec__` branch awaits `exec()`
2. `exec()` takes the `port` branch back to the same port, posts `{type:'exec'}`, parks
3. utility runs the handler, posts `__xpc_finish__` with **exec's** id
4. main's `__xpc_finish__` branch → `handleUtilityFinish` → unblocks step 2
5. step 1 resolves, posts `__xpc_finish__` with the **utility's** id
6. utility matches its own `pendingTasks` → `send()` resolves

Steps 3 and 5 do not collide: each side looks the id up only in its own map, so a wrong-direction
lookup is a miss and a no-op. Step 4 firing while step 1 is still awaiting is safe — an async
`port.on('message')` listener does not serialize subsequent message events.
