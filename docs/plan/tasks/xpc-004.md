# xpc-004 — Clean up routes when a utility process exits

## Objective

Remove every router record belonging to a utility process when it exits, and settle in-flight tasks
aimed at it with `null` instead of leaving them parked. Restores invariants 4 and 6.

Root cause: [../../issues/utility-exit-leaves-stale-routes.md](../../issues/utility-exit-leaves-stale-routes.md)

## Context

- [../../architecture/README.md](../../architecture/README.md) — §Lifecycle, §Invariants
- [../../issues/utility-exit-leaves-stale-routes.md](../../issues/utility-exit-leaves-stale-routes.md)

## Required design

### 1. `XpcTask` learns its target

`exec()`'s `port` branch sets `task.targetPortId = entry.id`. Add it as an optional field on
`XpcTask`; it stays `undefined` for main and renderer targets.

### 2. `xpcCenter.unregisterPort(portId)`

```text
unregisterPort(portId):
    ports.delete(portId)                                   # and the WeakMap entry via the port ref
    for [name, entry] of registry:
        if entry.type === 'port' && entry.id === portId: registry.delete(name)
    for [name, list] of subscribers:
        drop entries where type === 'port' && id === portId
        delete the key when the list becomes empty
    for task of pendingTasks.values():
        if task.targetPortId === portId: task.ret = null; task.unblock()
```

Scoped strictly to one portId. A second live utility process must keep every route and subscription.

### 3. Hook it up in `createUtilityProcess()`

| Hook | Why |
|---|---|
| `child.on('exit', …)` | load-bearing — covers crashes, not just explicit kills |
| `kill()` | keeps the synchronous path deterministic; `unregisterPort` must be idempotent since `exit` fires afterwards too |

`unregisterPort` on an unknown portId is a no-op, not an error.

## Path

- `src/main/xpcCenter.helper.ts`
- `src/main/xpcTask.helper.ts`
- `src/main/xpcMain.helper.ts`

## Constraints

- Mutating `registry` / `subscribers` / `pendingTasks` while iterating them: snapshot keys first
  (`[...map.entries()]`) rather than deleting mid-iteration.
- Do not add a general `send()` timeout. Invariant 4 is satisfied here by cleanup; timeouts are an
  explicit out-of-scope item in the feature doc.
- Do not extend this to destroyed renderers — that is a backlog item in a different layer.

| Check | Expected |

| Source review | cleanup is filtered by `portId`; no global clears |
